# Next.js static-export benchmark port

Port of the 4-stock demo site to **Next.js 16.4.0** (Pages Router, `output: 'export'`,
`trailingSlash: true`). Minimizes the diff against
`../../golden (the vendored harness target)` and documents the irreducible residue.

## Layout (authored files only)

- `next.config.js` — `output: 'export'`, `trailingSlash: true`
- `pages/_document.js` — `<Html lang="en">`, no extra markup
- `pages/index.js` — stock list; head via `next/head`, body via exact template string
- `pages/stocks/[ticker].js` — DATA-DRIVEN via `getStaticPaths` from `data.json`
  (uppercase tickers preserved, `fallback: false`)
- `lib/data.js` — build-time `data.json` loader (fs; imported only from
  `getStaticProps`/`getStaticPaths` so it never reaches the client bundle)
- `lib/html.js` — client-safe `esc()` (`AT&T` → `AT&amp;T`) + `BASE_URL`
- `scripts/prebuild.js` — manual PRE-BUILD step (see below)
- `public/` — generated by prebuild (gitignored): `sitemap.xml`, `robots.txt`, `style.css`

Inputs (`data.json` and `style.css`) are read from the folder in `DEMO_SITE_DIR`, which `run.py` stages from the harness folder.

## Build

```sh
npm install                 # pinned: next 16.4.0, react 19.3.0, react-dom 19.3.0 (npm ci also works)
npm run build               # npm auto-runs "prebuild": node scripts/prebuild.js, then next build
python3 ../../../compare.py out ../../golden
```

Clean build (delete `.next/` and `out/` first): ~1.3 s median-of-11.

### Why a manual pre-build sitemap script

Next has no sitemap convention for the Pages Router at all, and the App Router
convention (`app/sitemap.js` + `MetadataRoute.Sitemap`) emits a different XML shape
than the golden file. `scripts/prebuild.js` therefore renders `sitemap.xml` from
`data.json` (base `https://demo.example`, trailing-slash URLs) plus `robots.txt`
byte-exactly into `public/`, and copies the shared `style.css`. Files in `public/`
are passed through the export verbatim, so all three compare with 0 diff lines.

## Result

```
TOTAL raw=75 normalized=75 missing=[] extra_html=['404.html', '404/index.html']
```

Every HTML page contributes exactly 15 raw diff lines; `sitemap.xml`, `robots.txt`
and `style.css` are byte-identical. This is the floor for this golden target.

## Irreducible residue (what Next injects and why it can't go away)

`export const config = { unstable_runtimeJS: false }` on every page removes **all**
`<script>` tags and the `__NEXT_DATA__` payload (0 script tags in the 5 pages).
What remains, exactly **260 bytes per page** (uniform across all 5 pages):

1. **Minification** — Next emits the document as a single line; no pretty-print
   option exists. The 11 golden head lines (`<!DOCTYPE html>` … `<body>`) collapse
   into built line 1, and `</body>`/`</html>` merge into the final line. This alone
   is the whole 15-line diff per page: 11−/1+ at the head, 2−/1+ at the tail. Body
   lines survive only because they are injected as a newline-bearing template
   string via `dangerouslySetInnerHTML` (JSX text nodes cannot reproduce the golden
   newlines/indentation).
2. **`data-next-head=""`** marker attribute on all 8 head tags emitted through
   `next/head` (hydration bookkeeping, added in Next 13.2+, not removable).
3. **Forced viewport meta** — `<meta name="viewport" content="width=device-width"/>`
   is always injected by the Pages Router; it can be overridden but never removed.
4. **`<noscript data-n-css=""></noscript>`** — Head CSS bookkeeping stub.
5. **Hydration root** — `<div id="__next">…</div>` wrapper (plus one authored inner
   `<div>`, since `dangerouslySetInnerHTML` needs a host element).
6. Cosmetic: `charSet="utf-8"` casing and XHTML-style self-closing `/>` on void tags.

Residue outside the golden file set (doesn't count toward the diff, but ships):

- **Forced 404 pages** — `404.html` + `404/index.html` are always exported
  (reported as `extra_html`); there is no way to disable them.
- **Dead JS chunks** — `out/_next/` (~520 KB: turbopack runtime/framework/main
  chunks, `_buildManifest.js`, `_ssgManifest.js`, `_clientMiddlewareManifest.js`,
  and `_next/data/<buildId>/*.json`) is emitted even though **no HTML file
  references a single script**. Verified: adding a custom `pages/404.js` with
  `unstable_runtimeJS: false` still does not stop chunk emission.
